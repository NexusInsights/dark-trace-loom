# Stored-record alert scheduler

This preparation replaces the broken HTTP cron with the same five stored-record detectors used by the current app. It queries no external provider and requires no scheduler secret, pg_net or paid service. Supabase documents direct SQL/function cron jobs and a five-minute database-function example. [Cron quickstart](https://supabase.com/docs/guides/cron/quickstart), [Cron installation](https://supabase.com/docs/guides/cron/install).

The internal engine is SECURITY INVOKER, owned/executable by postgres only, with fixed pg_catalog search path, explicit owner filter and original can_access_case checks. The authenticated no-input wrapper is a narrowly guarded SECURITY DEFINER bridge: it derives auth.uid()/role, verifies a nonanonymous, undeleted, authenticated and unbanned Auth row, then passes only that owner to the same engine. The Edge route independently verifies Auth and calls this wrapper; it cannot send an actor override or perform separate notice/watermark writes. Native cron calls only the internal engine with a NULL global owner. Manual and cron aggregate logs have distinct actions/scopes.

| Original alert type | Preserved actual detector |
|---|---|
| domain_registration | Newly stored domain artifacts in the subject's case; no registration service queried |
| username_appearance | Newly stored case tool_results; a result alone does not establish a username match |
| data_change | Newly inserted case artifacts plus events; separate oldest25 samples and concatenated sorted IDs |
| mention_monitoring | Newly stored case entities; no external mention search |
| breach_detection | Up to250 raw case email/username/phone/domain identifier records, validated before exact deduplication; owner-filtered collected breach_records; severity/names derived only from the oldest25 sample |

All detectors preserve lower-exclusive created_at > COALESCE(last_checked,created_at), one captured upper-inclusive run time, realtime5-minute/hourly/daily/weekly preferences, oldest-due-first ordering and100-alert maximum. Count/sample pairs use one materialized source query. A row lock, native advisory lease and one per-alert subtransaction protect notification insertion and watermark advancement together; an error rolls back both. Aggregate errors contain static codes, never raw SQLERRM, secrets, subject names or identifiers. Whole-statement cancellation rolls back the invocation. PostgreSQL's native SHA256 needs no additional crypto extension. [Binary functions](https://www.postgresql.org/docs/17/functions-binarystring.html).

The original timestamp design has limits: a transaction committing later with an earlier/backdated created_at can fall behind an already advanced watermark; updates/deletes to old records are not new-record detections. Invalid oldest alerts can occupy a bounded batch until corrected. This is not a guaranteed event-delivery/outbox system. SQL lease busy returns an explicit409 through the Edge route. Cron history/SQL success alone is not in-app notification creation or reading, and private SMTP/email delivery is a separate integration.
