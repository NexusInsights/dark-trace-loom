# Person identification and background-verification methods

Primary-source research completed November 1, 2026. This is a practical 38-method inventory, not an exhaustive universe or a claim that these connectors are implemented. InsightNexus/shadowlogs project mapping remains separate. No real-person lookup, account registration, purchase, automation or deployment was performed.

## Best first priorities

1. Claim-level provenance, source artifacts, retrieval time, hashes and reviewer history.
2. Multilingual names and explainable human-reviewed identity resolution.
3. Corporate roles anchored to official company numbers, CIKs and LEIs with dates.
4. Professional licences verified against issuers and licence numbers.
5. Court lifecycle reconciliation: booking/accusation/activity/disposition/correction remain distinct.
6. Permitted official-source monitoring with before/after evidence and explicit unavailable/stale states.

P0: foundations before broad collection. P1: initial connectors/workflows. P2: specialized or permission-dependent. Acceptance criteria below are proposed engineering requirements, not universal legal standards.

## Full method catalog

| # / method and build source | Automation, access and licence | Identity evidence, ambiguity and acceptance |
|---|---|---|
| 1. P0 Purpose/consent/evidence intake. Build case scope, allowed sources, required authorizations and retention. [NIST proofing](https://pages.nist.gov/800-63-4/sp800-63a/proofing/). | Automate completeness/audit controls, not legal eligibility. Consumer-reporting use needs a separately designed process under [FTC guidance](https://www.ftc.gov/business-guidance/resources/background-checks-what-employers-need-know). | Block restricted connectors without their authorization. Minimize collected evidence; consent is not blanket permission for every source/use. |
| 2. P0 Multilingual names and declared professional aliases. Preserve original scripts, ordering, diacritics and sourced Latin forms. [W3C names](https://www.w3.org/International/questions/qa-personal-names), [internationalization](https://www.w3.org/TR/international-specs/). | Normalization/transliteration generates candidates, never overwrites originals or infers sensitive traits/undisclosed former names. | Test mononyms, patronymics, multiple surnames, reordering and non-Latin scripts. Variants are attributed strings, not identity proof. |
| 3. P0 Confusable-character detection. [Unicode UTS39](https://www.unicode.org/reports/tr39/). | Build using Unicode data and applicable licence. Confusable skeletons must not be used as identifier normalization. | Mixed-script lookalikes trigger review, never automatic identity merging; retain originals. |
| 4. P0 Explainable identity-resolution queue. Compare identifiers, public organizations, roles and dates. [NIST resolution/validation distinctions](https://pages.nist.gov/800-63-4/sp800-63a/proofing/). | Start deterministic. Similarity scores are not verified identities or calibrated probabilities. | Initially prohibit automatic person merges. Common-name collision tests must retain separate candidates; reviewers see agreement and contradiction evidence. |
| 5. P1 SEC corporate-role/filing verification. [EDGAR APIs](https://www.sec.gov/search-filings/edgar-application-programming-interfaces). | Public API/bulk data; [fair access](https://www.sec.gov/about/developer-resources) currently limits aggregate automation to 10 requests/second. Identify traffic and cache. Attachment reuse rights vary. | Anchor CIK/accession, filing date and exact role assertion. A filing name alone is not person identification or current employment. |
| 6. P1 Companies House companies/officers/appointments. [API overview](https://developer.company-information.service.gov.uk/overview). | API credentials; [600 requests/five minutes](https://developer.company-information.service.gov.uk/developer-guidelines/). Review reuse/personal-data terms before redistribution. | Keep company number, officer resource, appointment/resignation and source filing. Same-name officers remain candidates pending corroboration. |
| 7. P1 State corporate registries for smaller businesses. [Texas SOSDirect](https://www.sos.state.tx.us/corp/sosda/index.shtml). | Jurisdiction-specific manual/approved adapters; [published Texas fees](https://www.sos.state.tx.us/corp/forms/806_boc.pdf). Site returned403 to research tool; no public automation API established. | Resolve by jurisdiction+registration number. Preserve registry artifact/time; exclude residential/contact fields. |
| 8. P1 LEI and parent-entity reconciliation. [GLEIF API](https://www.gleif.org/en/lei-data/gleif-api/), Golden Copy/deltas. | [GLEIF data CC0](https://www.gleif.org/en/meta/lei-data-terms-of-use), subject to access-service terms. | LEI identifies an entity, not a natural person. Preserve status, effective dates and reporting exceptions; do not invent ownership. |
| 9. P1 Issuer-board professional licence checks. [TDLR](https://www.tdlr.texas.gov/verify.htm), [Texas dental primary-source verification](https://tsbde.texas.gov/resources/public-license-search/). | Per-board APIs/exports only when documented/authorized; otherwise manual evidence/link-out. Public visibility does not establish unrestricted reuse. | Match issuer+licence number/type. Distinguish active, expired, suspended and other issuer statuses. |
| 10. P1 NPI professional identifier. [CMS registry/API](https://npiregistry.cms.hhs.gov/). | CMS API/downloads; bulk queries use downloadable files. Allowlist professional identifiers, excluding addresses/contact aggregation. | CMS explicitly says NPI issuance does not validate licensing/credentials. A licence claim requires a separate board check. |
| 11. P2 Broker/adviser registration/disclosures. [IAPD](https://www.investor.gov/introduction-investing/getting-started/working-investment-professional/using-iapd), FINRA BrokerCheck. | Begin manual. [FINRA API terms](https://developer.finra.org/finra-api-terms-service) govern approved datasets; programme access is not unrestricted BrokerCheck automation rights. | Anchor CRD/SEC ID; preserve history and precise disclosure status. Complaint/pending matter is not final finding. |
| 12. P2 NMLS registration/licence verification. [Consumer Access terms](https://mortgage.nationwidelicensingsystem.org/knowledge/Products/consumeraccess/SitePages/Consumer-Access-Terms-of-Use.aspx). | Manual or expressly licensed route until machine-access permission is established. | Match NMLS ID plus jurisdiction/activity. Registration is not authorization for every activity in every state. |
| 13. P2 ORCID researcher identity/source assertions. [ORCID searching/authenticated IDs](https://info.orcid.org/documentation/api-tutorials/api-tutorial-searching-the-orcid-registry/). | [Public API terms noncommercial](https://info.orcid.org/public-client-terms-of-service/); [public file CC0](https://info.orcid.org/public-data-file-use-policy/). Commercial API use needs suitable agreement. | Search hit is candidate; authenticated iD establishes account control. Each affiliation/work still retains its own source/dates. |
| 14. P2 Scholarly-work/author corroboration. [Crossref REST](https://www.crossref.org/documentation/retrieve-metadata/rest-api/). | Public metadata; current access guidance and item-level rights apply, especially abstracts/full text. | DOI anchors work, not person. Corroborate same-name authors and retain corrections/post-publication updates. |
| 15. P1 Institution-name normalization. [ROR](https://ror.org/registry/), [versioned dumps](https://ror.readme.io/docs/data-dump). | CC0 data/open API. | Preserve ROR ID and source assertion; institution resolution is not proof of a person's employment. |
| 16. P2 Official grant/project roles. [NSF API](https://www.nsf.gov/digital/developer), [NIH RePORTER](https://api.reporter.nih.gov/). | Public programme APIs; check current endpoints/terms and allowlist fields. Omit phone/email/address fields. | Anchor award/project ID, agency, institution and dates. Published PI name corroborates that project role, not identity/current employment alone. |
| 17. P2 Patent inventor/assignee corroboration. [USPTO Open Data Portal](https://data.uspto.gov/apis/getting-started). | Public data/API routes with current account/key/terms requirements; no account/key created. | Anchor publication/application number, role and date. Do not infer current employment; discard residential fields. |
| 18. P2 Library authority/cross-language variants. [VIAF API](https://www.oclc.org/developer/api/oclc-apis/viaf.en.html). | Current OCLC documentation specifies ODC-BY attribution; API limits/access require separate verification. | Keep authority/control numbers and contributor records. Authority clusters can be wrong and must remain correctable. |
| 19. P1 OFAC candidate review. [Sanctions List Service](https://ofac.treasury.gov/sanctions-list-service). | Version published files and apply access controls. Never turn a name score into an adverse decision. | [OFAC potential-match guidance](https://ofac.treasury.gov/faqs/5) requires complete-entry review/corroboration. Test common-name false positives; human sign-off. |
| 20. P2 UK/UN sanctions coverage. [UK Sanctions List](https://www.gov.uk/government/publications/the-uk-sanctions-list), [UN XML/list](https://main.un.org/securitycouncil/en/content/un-sc-consolidated-list). | Published formats/reuse terms. Old OFSI consolidated list closed28Jan2026 and is stale. | Preserve regime/reference/designation ID, aliases/status/update time. Separate jurisdictions; no name-only sanction assertion. |
| 21. P1 SAM public exclusions. [GSA API](https://open.gsa.gov/api/exclusions-api/), [extracts](https://open.gsa.gov/api/sam-entity-extracts-api/). | API key/account quotas/current version; do not mix public/restricted fields. | Keep exclusion ID, agency, scope, active/end dates. Procurement exclusion is not a generic criminal finding/universal prohibition. |
| 22. P2 HHS-OIG exclusions. [LEIE downloads/supplements](https://oig.hhs.gov/exclusions/leie-database-supplement-downloads/). | Official CSV/local processing. Unique verification involving sensitive identifiers stays in an authorized issuer workflow, not app collection by default. | [OIG says first+last-name match is insufficient](https://oig.hhs.gov/exclusions/leie-quick-tips-instructions/). Unresolved candidates stay unresolved; apply reinstatement changes. |
| 23. P2 World Bank procurement sanctions. [Official list/decisions](https://www.worldbank.org/en/Projects-operations/procurement/debarred-firms). | Manual/approved export; no documented automation API established here; check reuse terms. | Preserve sanction type/grounds/dates/cross-debarment conditions. Do not collapse conditional outcomes into a universal blacklist. |
| 24. P2 Official court docket retrieval. [Current PACER Case Locator API](https://pacer.uscourts.gov/sites/default/files/files/PCL-API-10-2026.pdf). | Paid/account-dependent; searches may incur fees even without matches. [Policies prohibit billing-avoidance collection](https://pacer.uscourts.gov/policy-procedures). Require a retrieval budget. State/local routes separate. | Key court+case number+party role. No result in searched coverage does not establish no court history. |
| 25. P1 Court lifecycle/disposition reconciliation. Model booking/arrest/filing/charge/hearing/dismissal/judgment/appeal/correction separately. [FTC accuracy concerns](https://www.ftc.gov/business-guidance/resources/what-tenant-background-screening-companies-need-know-about-fair-credit-reporting-act). | Extract and flag missing outcomes, with human-reviewed conclusions. Consumer-reporting rules apply when in scope. | Never turn booking/dismissal into conviction; deduplicate same matter; preserve later disposition/correction and sealed/expunged-record handling. |
| 26. P2 RECAP/CourtListener discovery/corroboration. [RECAP APIs](https://wiki.free.law/c/courtlistener/help/api/rest/v4/recap). | Authentication/tiers/terms; cached coverage incomplete; paid PACER fetch is separate, never automatic fallback. | Preserve RECAP and court/document IDs. Missing cached document is not absence; important conclusions cite court records. |
| 27. P2 Authorized official-record request workflow. [FOIA guidance](https://www.foia.gov/faq.html). | Consent/request tracker, not unrestricted person API. Privacy exemptions, agency rules, submissions and fees require specific authorization. | Track agency/scope/authorization/redactions/status. Withheld/unavailable record is not an adverse fact. |
| 28. P2 Consent-based education/qualification verification. [Clearinghouse/issuer route](https://www.studentclearinghouse.org/verify/). | Manual issuer or contracted connector; [terms restrict unauthorized automated extraction](https://www.studentclearinghouse.org/terms-of-use/). | Preserve issuer/programme/award date/verification evidence. Distinguish unable-to-verify, hold and not-awarded. |
| 29. P2 Voluntarily supplied verifiable credentials. [W3C VC2.0](https://www.w3.org/TR/vc-data-model-2.0/). | Standards-based verifier; separately select library/issuer agreements. Trust policy, expiry/status/replay controls required. | Valid signature does not prove all claims true. Test revoked/expired/wrong-issuer/altered credentials. |
| 30. P1 Official professional biography/affiliation corroboration. [NIST validation distinction](https://pages.nist.gov/800-63-4/sp800-63a/proofing/). | Permitted limited/manual capture; site terms/copyright. Label institutional assertions separately from self-asserted profiles. | Preserve publisher/URL/claim/date. Historical bio is not current employment; account existence is not resolved identity. |
| 31. P1 Page-anchored multilingual OCR. [Tesseract](https://tesseract-ocr.github.io/tessdoc/). | Apache2.0 engine; verify language-asset licences/deployment separately. No installation performed. Resource limits and originals preserved. | Low-confidence fields require review; each name/date/ID links to page/region. OCR confidence is not identity confidence. |
| 32. P1 Safe file text/metadata extraction. [Apache Tika](https://tika.apache.org/). | Apache2.0; isolated parser with time/size limits. [Security model](https://tika.apache.org/security-model.html) warns input and output may be hostile. | Metadata can be forged. Test malformed files, active links, formula injection and honest extraction errors. |
| 33. P2 Signed-document validation. [European Commission DSS](https://ec.europa.eu/digital-building-blocks/sites/spaces/DIGITAL/pages/467109107/Digital%2BSignature%2BService%2B-%2BDSS). | LGPL2.1 obligations; maintain trust lists/certificate validation; services have separate terms. | Separate integrity, certificate trust, signing time and content truth. Signature validity alone is not factual verification. |
| 34. P0 Temporal reconciliation. [OWL-Time instants/intervals](https://www.w3.org/TR/owl-time/). | Deterministic handling, preserving source timezone/precision. No invented day/time for month/year evidence. | Former role is not current merely because end date absent. Keep event/publication/retrieval times and contradictions distinct. |
| 35. P0 Claim-level provenance graph. [W3C PROV-O](https://www.w3.org/TR/prov-o/). | Custom standards-based entity/activity/agent model; original-record rights remain. Preserve parser/version/reviewer. | Every derived claim links evidence/transformation. Repeated copies of one source do not count as independent corroboration. |
| 36. P0 Evidence capture/preservation. [WARC](https://iipc.github.io/warc-specifications/guidelines/warc-implementation-guidelines/), [NISTIR8387](https://www.nist.gov/publications/digital-evidence-preservation-considerations-evidence-handlers). | Capture only permitted originals/metadata/hashes; copyright/access/retention apply. Redact credentials/cookies and unrelated personal content. | Detect alteration and preserve acquisition/audit history. Hash consistency is not truth, lawful collection or automatic admissibility. |
| 37. P1 Permitted source monitoring/diffs/corrections. [Companies House stream](https://developer-specs.company-information.service.gov.uk/streaming-api/guides/overview), official deltas, [HTTP conditional requests](https://www.rfc-editor.org/rfc/rfc9110.html). | Approved sources/schedule/rate/terms only; authenticate webhooks where supported; bounded polling. | Before/after evidence; distinguish content change, removal, timeout, access failure and stale cache. Outage must not create adverse claim. |
| 38. P0 Review/correction/quality/reproducible export. [BagIt checksums](https://www.rfc-editor.org/rfc/rfc8493.html), [precision/recall/confusion matrices](https://scikit-learn.org/stable/modules/model_evaluation.html). | Access-controlled exports preserve licences/redactions; human approval/rejection and correction history. No employment/eligibility scoring. | No automatic cross-person merges initially; explicit unknowns/contradictions; verify export checksums; corrections propagate without erasing audit trail. |

## Findings that change implementation decisions

- ORCID CC0 public-data rights do not grant commercial Public API access. Use the licensed route or CC0 file as appropriate.
- CMS NPI is not licence verification.
- UK OFSI consolidated list is no longer current after28Jan2026.
- The CFPB2021 name-only advisory was [withdrawn12May2025](https://www.consumerfinance.gov/compliance/guidance/withdrawn-guidance/). Do not cite it as current binding guidance. Avoiding name-only merges remains a proposed accuracy rule; applicable statute/currentFTC obligations need separate treatment.
- A publicly visible record is not automatically a freely reusable commercial dataset. Connector gates must track credentials, quotas, permitted uses, fees and attribution.
- Default ingestion excludes private address/phone/email aggregation, biometrics, sensitive-trait inference, covert tracking, credential leaks and employment-eligibility scoring. Retain only necessary identifiers, professional/business roles, dates/status and provenance.
